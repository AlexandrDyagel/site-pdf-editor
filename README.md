# PDF Редактор — веб-приложение для аннотирования PDF

Клиентское приложение для загрузки, просмотра, аннотирования и экспорта PDF-документов.
Работает целиком в браузере: сервер не требуется, файлы пользователя никуда не отправляются.

**Стек:** Vue 3 (Composition API, `<script setup lang="ts">`), TypeScript, Vite, Tailwind CSS,
Pinia, Konva, pdfjs-dist, pdf-lib + @pdf-lib/fontkit, perfect-freehand, IndexedDB (idb), JSZip, docx.

### Если что-то не работает

**Пустая рабочая область вместо страницы PDF.** Проверьте, что dev-сервер жив: в
терминале должно быть `VITE ... ready`, а в консоли браузера — ни одной ошибки.
Приложение рисует страницу на Konva-сцене; если слои сцены не подключены
(`stage.add(layer)`) или падает worker pdf.js, область остаётся пустой
(миниатюры при этом могут работать).

**`EBUSY: resource busy or locked, watch '...'` и dev-сервер исчезает.** На Windows
любой заблокированный файл внутри проекта (профиль браузера, временный файл
антивируса или редактора, атомарная запись) убивает файловый watcher Vite, и
сервер завершается. В проекте это уже обработано: `vite.config.ts` игнорирует
`dist`, `.tmp`, скрытые каталоги и `*.tmp`, а плагин `watcher-error-guard`
гасит ошибки `EBUSY/EPERM/EACCES/ENOENT` вместо падения процесса. Если вы
добавляете собственные каталоги с блокируемыми файлами — допишите их в
`server.watch.ignored`.

**Правки в коде не видны в браузере (приложение «показывает старое»).** На Windows
файловый watcher Vite иногда умирает (см. пункт про `EBUSY` выше): процесс жив и
отдаёт страницу, но перестаёт замечать изменения, поэтому в браузере остаётся
старый модуль (иногда свежий скрипт компонента и устаревший шаблон). Симптом:
кнопки, добавленные в коде, не появляются, в консоли ошибка вида `X is not
defined` для только что добавленной функции. В `vite.config.ts` включён
`server.watch.usePolling` — опрос файлов не пропускает правки, так что проблема
не возникает; если сервер всё же отдаёт старое, перезапустите `pnpm dev` и
проверьте, что он отдаёт свежий файл:
`(Invoke-WebRequest http://127.0.0.1:5173/src/App.vue).Content`. Проверка
интерфейса: `pnpm check:font-ui`.

**Кнопка в интерфейсе ничего не делает, а окно «всплывает» позже.** Так было с
«Управление шрифтами»: окно было смонтировано только в редакторе, а кнопка в
настройках лишь выставляла флаг. Теперь окна, которые открываются с любой
страницы (шрифты, горячие клавиши, библиотека изображений, проекты), подключены в
`App.vue`, а при переходе между страницами все окна закрываются
(`router.afterEach`). Новые общие окна подключайте там же, а не в `EditorView`.

**Добавил картинку, а видна только рамка.** Узел `Konva.Image` хранит битмап в
атрибуте, а не разрешает его при отрисовке: если изображение ещё грузилось,
узел создавался с `image: undefined` и оставался пустым. Теперь готовность
битмапов входит в подпись структуры узла (`resourcesSignature` в
`konvaObjectFactory`), а загрузка ресурса вызывает полную синхронизацию
(`onReady → sync`), поэтому картинка появляется сразу после декодирования.
Проверка: `pnpm check:canvas-tools`.

**Курсор корректора.** Для кисти, маркера и корректора системный курсор скрыт
(`cursor: none`), вместо него рисуется кружок по размеру кисти с учётом
масштаба — он же обновляется при изменении размера в настройках инструмента.
Для фигур и текста остаются крестик и текстовый курсор.

**Рисование обрывается или штрих пропадает.** Инструменты рисования захватываютуказатель (`setPointerCapture` на `.konvajs-content`), поэтому штрих продолжается,
даже если курсор ушёл на панель или за окно, а отпускание кнопки вне холста
завершает штрих. Дополнительно: незавершённый жест доводится до конца перед
началом нового (раньше он молча терялся при следующем нажатии), а отпускание
кнопки/отмена указателя/потеря фокуса окна обрабатываются на уровне `window`.
Проверка: `pnpm check:corrector`.

**Библиотека/проект не сохраняются, в консоли `could not be cloned`.** IndexedDB
не умеет копировать реактивные Proxy-объекты Vue, а шаблоны штампов, подписи и
объекты редактора приходят из Pinia. Любая запись в базу проходит через
`toPlain()` (`src/utils/clone.ts`) в `storageService`. Если добавляете новое
хранилище — используйте `toPlain()` для данных из сторов. Проверка:
`pnpm check:interaction`.

**Проверка в браузере без участия человека.** `pnpm check:workflow` поднимает
headless Chrome (нужен установленный Chrome или Edge), загружает тестовый PDF
с кириллицей, печатает текст, вставляет штамп, рисует от руки, проверяет
undo/redo, экспортирует PDF/PNG/JSON, затем заново открывает экспортированный
PDF и убеждается по пикселям, что аннотации действительно попали в файл в
нужные места. Скриншоты шагов сохраняются в `.tmp/`.

`pnpm verify` собирает `scripts/verify-logic.ts` через esbuild и проверяет в Node:
конвертацию координат для всех поворотов страницы (включая смещённый MediaBox),
совпадение положения объектов с предпросмотром при векторном экспорте в PDF,
определение кодировок UTF-8/windows-1251/koi8-r, перенос строк текста,
контуры рукописных штрихов, наличие всех файлов шрифтов, покрытие кириллицы
и успешное встраивание TTF в PDF (а также ожидаемую ошибку при попытке записать
кириллицу стандартным Helvetica).

Скрипт `scripts/copy-pdfjs-assets.mjs` автоматически копирует стандартные шрифты и
таблицы CMaps из `node_modules/pdfjs-dist` в `public/pdfjs` (запускается перед `dev` и `build`),
чтобы рендер работал без интернета.

## Возможности

**Документ**
- загрузка PDF перетаскиванием, через диалог или открытие проекта;
- корректная работа с защищёнными паролем файлами (запрос пароля, предупреждения);
- понятные сообщения об ошибках для повреждённых, пустых и слишком больших файлов;
- миниатюры страниц с ленивой загрузкой, кэш отрисованных страниц;
- создание пустого документа (A4/A5/A3/Letter/Legal).

**Инструменты**
- выбор/перемещение, панорамирование, зум (колесо, Ctrl+колесо, пресеты, «вписать»);
- текст с выбором шрифта, размера, цвета, выравнивания, межстрочного и межбуквенного
  расстояния, фона, тени и автовысоты. **Ввод идёт прямо на холсте:** клик
  инструментом «Текст» ставит мигающую каретку, текст набирается сразу, а рамка
  растёт по содержимому (см. «Редактирование текста на холсте»);
- изображения (вставка, замена, библиотека, вписывание, скругление, рамка);
- фигуры: прямоугольник, эллипс, треугольник, многоугольник, линия, стрелка
  (штриховые линии, заливка, скругление, наконечники);
- рисование от руки: кисть, маркер, корректор (мышь, палец, стилус, давление пера);
- закрашивание (whiteout) и выделение (highlight) областей;
- подписи от руки с сохранением в библиотеку;
- штампы и печати: прямоугольные/круглые/овальные, текст по прямой и по кругу,
  двойная рамка, разделитель, логотип, прозрачность, поворот;
- выделение области, группировка, выравнивание, распределение, порядок слоёв,
  блокировка, скрытие, дублирование, перенос на другую страницу, перенос штампа на все страницы.

**Текст из PDF**
- на панели «Текст PDF» строится текстовый слой страницы (pdf.js);
- «Заменить» закрывает исходный фрагмент закрашиванием и добавляет новый текст
  (корректурный слой) — это надёжнее прямой правки PDF и гарантирует корректную кириллицу;
- Alt + клик инструментом «Текст» делает то же самое прямо на странице.

**Экспорт**
- PDF с аннотированиями (исходные страницы сохраняются, текст остаётся текстом);
- плоский PDF (растеризация страниц);
- PNG / JPEG / WebP: постранично, в ZIP-архиве или одним длинным изображением, с выбором DPI;
- DOCX: страницы изображениями + текст аннотаций;
- проект JSON (объекты + метаданные + настройки + опционально исходный PDF);
- SVG для штампов, печатей, подписей и рисунков;
- экспорт/импорт библиотек и отдельных элементов.

**Интерфейс**
- полностью русский, с тёмной и светлой темами;
- панели: страницы, библиотека, текст PDF, инструмент, свойства, слои, страница;
- модальные окна: конструктор штампа, редактор подписи, редактор рисунка, экспорт,
  шрифты, библиотека изображений, проекты, свойства документа, горячие клавиши;
- состояния загрузки, пустые состояния, подтверждения опасных действий, тултипы,
  горячие клавиши, адаптивная вёрстка (панели-оверлеи на планшете).

## Кириллица: почему текст не превращается в «кракозябры»

1. Все строки внутри приложения — Unicode/UTF-8, JSON-проекты пишутся в UTF-8.
2. В PDF встраиваются настоящие TTF-шрифты (PT Sans, Roboto, Inter, Noto Sans, DejaVu Sans,
   DejaVu Serif, PT Mono) через `@pdf-lib/fontkit`.
3. Стандартные шрифты PDF (Helvetica/Times в WinAnsi) для русского текста **не используются**.
4. Перед экспортом проверяется покрытие глифов: если в выбранном шрифте нет символов,
   приложение предупреждает и подставляет шрифт с поддержкой нужных символов.
5. Пользователь может загрузить свой TTF/OTF (например, Times New Roman) — шрифт сразу
   используется для предпросмотра и встраивается в PDF (хранится в IndexedDB).
6. Предпросмотр и PDF используют один и тот же шрифт и один алгоритм раскладки текста,
   поэтому переносы строк и позиции совпадают.
7. Метаданные PDF (автор, название, тема, ключевые слова) пишутся pdf-lib в UTF-16BE.
8. CSV/TXT/JSON сохраняются в UTF-8 (CSV — с BOM), чтение текстовых файлов поддерживает
   UTF-8, windows-1251, koi8-r и windows-1252 с автоопределением кодировки.
9. Имена файлов сохраняются корректно (Blob + `download`, `sanitizeFileName`,
   `filename*` по RFC 5987 при серверной отдаче).

### Встраивание шрифтов: подмножества pdf-lib повреждают часть шрифтов

Отдельная важная деталь, найденная автоматической проверкой
(`pnpm check:fonts` → `scripts/check-font-subsets.mjs`): подмножества
(`embedFont(bytes, { subset: true })`) **портят глифы** у части шрифтов. Проверка строит
два PDF (с подмножествами и с полным встраиванием), рендерит их в headless-браузере
постранично (начертания раскладываются по страницам, поэтому проверяются все 63) и
сравнивает заполнение строк пикселями. Результат:

| Шрифт | Подмножество | Решение |
| --- | --- | --- |
| PT Sans (4 начертания), Roboto (5), DejaVu Serif (1), Manrope (2), Rubik (3), IBM Plex Sans (3), Cormorant (3), Merriweather (3), Montserrat (3), Raleway (3), Source Sans 3 (3), Fira Code (2), Golos Text (2), Open Sans (3) | корректно | встраивается подмножеством (файл маленький) |
| Inter (2), Noto Sans (2), PT Mono (1), DejaVu Sans (3), Tinos (3), Liberation Sans (3), PT Serif (3), Fira Sans (3), Ubuntu (3) | **глифы пропадают** | встраивается целиком |

Поэтому в `public/fonts/fonts.json` у каждого шрифта есть флаг `subsetSafe`, а
`fontService.embedFont()` выбирает режим встраивания. Пользовательские шрифты
проверяются автоматически при загрузке (`src/services/fontSubsetCheck.ts`): для
файла строятся два пробных PDF (подмножество и полное встраивание), они
рендерятся через pdf.js, и «чернила» сравниваются. Совпало — шрифт встраивается
подмножеством (Times New Roman: 73 КБ вместо 2,4 МБ), не совпало — целиком.
Плата за корректность — размер файла: например, документ с PT Mono вырастает
примерно на 90 КБ. В окне «Шрифты» показано, как встраивается каждый шрифт.

Дополнительно `pnpm check:font-embed` проверяет каждое начертание иначе: строит PDF,
встраивает шрифт, пишет кириллическую строку и **извлекает текст обратно** через
pdf.js. Так ловится уже не отрисовка, а кодировка: если подмножество испорчено,
строка вернётся обрезанной (63/63 начертания проходят).

Файл манифеста запрашивается с `cache: 'no-cache'`, иначе браузер мог бы использовать
старую версию без флагов; дополнительно в `fontService` есть страховочный список
`SUBSET_UNSAFE_FONT_IDS`.

### Встроенные шрифты: 23 семейства, 63 начертания

Кроме базовых PT Sans / Roboto / Inter / Noto Sans / DejaVu добавлены
**Tinos, Manrope, Liberation Sans, Rubik, IBM Plex Sans, Cormorant, Merriweather,
PT Serif, Montserrat, Raleway, Fira Sans, Source Sans 3, Ubuntu, Fira Code,
Golos Text, Open Sans** — с настоящей кириллицей, начертаниями 400/700 и курсивом
(где он есть), всего 63 файла в `public/fonts`.

Как готовятся файлы (одна команда, если нужно повторить):

```bash
python scripts/tools/prepare-bundled-fonts.py --out public/fonts --report .tmp/fonts-report.json
node scripts/install-bundled-fonts.mjs   # проверяет файлы и правит fonts.json
```

* часть семейств в репозитории Google Fonts лежит **вариативными** файлами
  (`Montserrat[wght].ttf` и т. п.). Вариативный файл встраивать нельзя: fontkit
  возьмёт экземпляр по умолчанию (например, Montserrat Thin). Поэтому
  `scripts/tools/prepare-bundled-fonts.py` через `fontTools.varLib.instancer`
  закрепляет вес 400/700 и сохраняет статический TTF;
* там же файлы уменьшаются до наборов символов, которые реально нужны
  (латиница, кириллица, греческий, пунктуация) — 21,7 МБ превращаются в 15,9 МБ;
* Liberation Sans нет в Google Fonts — он берётся из пакета `fonts-liberation2`
  (переменная окружения `LIBERATION_DIR`).

После установки каждая проверка подтверждает результат:

| Проверка | Что проверяет | Результат |
| --- | --- | --- |
| `pnpm check:font-embed` | встраивание + извлечение текста для каждого начертания | 63/63 |
| `pnpm check:fonts` | подмножества против полного встраивания (пиксели) | помечено `subsetSafe` |

## Координаты и масштабирование

- Внутренняя система координат — **PDF points** (1 pt = 1/72"), origin в левом верхнем углу
  страницы, ось Y вниз (как в canvas/Konva).
- Зум и панорамирование влияют **только на отображение**: `stage.scale/position`,
  координаты объектов не меняются.
- Конвертация в систему PDF (origin снизу-слева, Y вверх) выполняется утилитами
  `konvaToPdfCoordinates`, `pdfToKonvaCoordinates`, `localPointToPdf`, `getPdfObjectRotation`
  (`src/utils/coordinates.ts`); формулы совпадают с `pdf.js PageViewport`, поэтому страницы
  с `/Rotate 90/180/270` и смещённым MediaBox обрабатываются корректно.
- Дополнительно: `normalizeObjectToPage`, `scaleObjectForExport`, `getTransformForPage`,
  `remapObjectToPage`, `dpiToScale`.
- Экспорт изображений: масштаб `1x/2x/3x/4x` или DPI (72…600), при этом `scale = dpi / 72`.

## Панели редактора

- **Кнопки разделов не обрезаются.** Если разделы («Страницы / Библиотека / Текст PDF»
  слева, «Инструмент / Свойства / Слои / Страница» справа) не помещаются в ширину
  панели, они переносятся на следующую строку целиком, а когда места снова
  достаточно — возвращаются в один ряд. Реализовано в `AppTabs`:
  `flex-wrap` + `grow shrink-0 basis-auto`, текст вкладки никогда не сжимается.
- **Ширину панелей можно менять.** Потяните за внутреннюю границу панели
  (курсор ↔) — панель расширяется к центру рабочей области. Двойной клик по
  границе возвращает исходную ширину, стрелки на границе меняют её с клавиатуры.
  Ширина сохраняется между сессиями в `localStorage`
  (`pdf-editor:panel-widths`); ограничения — 220…720 px и не более 45% окна
  (`src/composables/usePanelLayout.ts`). Содержимое панелей при этом прокручивается.
- **Выбор инструмента сразу открывает его настройки.** Клик по иконке
  инструмента (или горячая клавиша) переключает правую панель на вкладку
  «Инструмент» и открывает панель, если она была закрыта — размер кисти, цвет и
  прочие параметры видны до первого действия. Для инструмента «Выбор» вкладка не
  меняется, чтобы не перекрывать свойства объекта.
- **Действие на холсте открывает «Свойства».** Нарисовали фигуру, вставили штамп
  или выделили объекты рамкой — правая панель показывает свойства нового объекта
  (`addFromCanvas` в `useEditorTools`). А вот одиночный клик по строке в панели
  «Слои» только выделяет объект и **не** переключает вкладку (даже если выбран
  рисующий инструмент); свойства оттуда открываются двойным кликом.
- Проверка: `pnpm check:layout` (27 проверок: видимость разделов, перенос строк,
  перетаскивание, сохранение ширины, двойной клик, клавиатура, автопоказ
  настроек инструмента и «Свойств» после рисования).

### Панель «История»

Правая панель, вкладка сразу после «Слоёв». Лента действий: сверху — что было
сделано, ниже — **текущее состояние** (отмечено «сейчас»), ещё ниже — отменённые
действия, которые можно вернуть.

- Клик по любой строке переносит документ в это состояние: `undo`/`redo`
  прокручиваются столько раз, сколько нужно, — не надо нажимать «Отменить»
  несколько раз подряд.
- Кнопки **«Отменить»** и **«Повторить»** дублируют `Ctrl+Z` / `Ctrl+Shift+Z` и
  блокируются, когда шагов нет; в подсказке — название ближайшего действия.
- Внизу — счётчик шагов и лимит истории (`HISTORY_LIMIT`), у каждого действия
  видно время. Пустая история показывает заглушку.
- **Одна правка — один шаг.** Переименование объекта, набор текста и перетаскивание
  ползунков пишут в историю один шаг на всю правку, а не на каждую букву:
  снимок делается перед первой правкой (`onRenameInput` в `PropertiesPanel`),
  дальше значения меняются без записи в историю.
- Проверка: `pnpm check:history` (20 проверок: порядок вкладки, пустое состояние,
  подписи действий, переход по клику в начало и обратно, кнопки, «десять букв —
  один шаг»).

### Фигуры: треугольник и многоугольник

- **Треугольник** (`Y`) и **многоугольник** (`N`) рисуются рамкой, как остальные
  фигуры, и имеют те же параметры: обводка (в том числе «Без цвета»), толщина,
  заливка, штриховая линия.
- **Скругление углов** — есть у прямоугольника, треугольника и многоугольника
  (поле «Скругление, pt» в свойствах и ползунок в параметрах инструмента).
- **Количество углов** многоугольника — от 3 до 24 (по умолчанию 5): ползунок в
  параметрах инструмента и числовое поле в свойствах.
- Геометрия считается один раз в `src/utils/shapePath.ts` и используется обоими
  рендерерами: `Konva.Path` на холсте и `page.drawSvgPath` в PDF, поэтому форма в
  редакторе и в файле совпадает. Скругление — квадратичные кривые через вершину.
- **Черновой контур при растягивании** повторяет будущую фигуру: у треугольника и
  многоугольника видно сам многоугольник, а не рамку (как у круга рисуется круг).
- **Многоугольник заполняет рамку целиком** — иначе треугольник занимал бы только
  75 % высоты и внизу оставалась пустая полоса; вершины нормируются по
  собственным границам фигуры.
- **Числовые поля** фиксируют значение при потере фокуса: можно набрать «12» или
  «23» — после первой цифры минимум больше не подставляется (иначе в поле с
  `min="3"` получалось «3»). Ограничение `min/max` применяется по `blur`/Enter
  (`AppInput`).
- **Shift при рисовании:** у прямоугольника — квадрат, у эллипса — круг, у
  многоугольника — многоугольник, вписанный в квадрат, у треугольника — рамка
  **правильного** треугольника (высота = сторона × √3/2, иначе он был бы только
  равнобедренным), у линии и стрелки — угол, кратный 45°. Подсказка в параметрах
  инструмента своя для каждого инструмента (`shapeHint` в `ToolOptionsPanel`),
  а предпросмотр показывает уже ограниченную фигуру (`squareFromPoints`,
  `equilateralTriangleBox`, `snapPointToAngle` в `src/utils/geometry`).
- Проверка: `pnpm check:shapes-extra` (37 проверок: рисование, контур черновика,
  Shift для всех фигур, подсказки, число углов и скругление, набор «12»/«23»,
  названия слоёв, PDF).

### Подсказки (тултипы)

Подсказки к иконкам инструментов и кнопкам панелей рендерятся **телепортом в
`body`** с `position: fixed` и высоким `z-index` (`AppTooltip`). Иначе они
пропадают: шапка редактора использует `backdrop-blur`, а он создаёт собственный
контекст наложения, поэтому `absolute z-50` внутри шапки оказывается **ниже**
холста и боковых панелей. Плюс панели обрезают содержимое через `overflow-hidden`
— подсказка у края панели обрезалась. Теперь положение считается по
`getBoundingClientRect` кнопки, пузырёк не выходит за пределы окна (при нехватке
места смещается или показывается над элементом) и скрывается при прокрутке.
Проверка: `pnpm check:tooltips` (33 кнопки шапки, все 29 иконок инструментов,
подсказки в панели, скрытие при уходе курсора).

### Горячие клавиши и раскладка

Сочетания работают при **любой раскладке**, включая русскую. Клавиша берётся не
из `event.key` (при русской раскладке физическая Z даёт «я», и Ctrl+Z не
срабатывал), а из `logicalKey()`: латинская буква или цифра — как есть, иначе
переводится физический код клавиши (`event.code`). Это касается и буквенных
сокращений инструментов (`B` — кисть, `E` — корректор…), и клавиш `[` / `]`.
Стрелки, `Escape`, `Delete`, `Home`, `End`, `PageUp/PageDown` от раскладки не
зависят. Проверка: `pnpm check:hotkeys` (эмуляция русской раскладки: Ctrl+Z/Y,
Ctrl+A/C/V, `[`/`]`, буквы инструментов, Delete, Ctrl+E, Ctrl+1, двойной клик по
тексту).

Клавиши не перехватываются, пока фокус в поле ввода — поэтому при **явном**
редактировании текста (двойной клик по объекту, кнопка в панели слоёв, создание
текста) сочетания вроде Ctrl+Z работают с текстом, а не с документом. При
обычном выделении объекта фокус в поле не ставится, поэтому горячие клавиши
продолжают работать.

### Порядок слоёв

- **Свойства объекта:** кнопки «Поверх» (на самый верх) и «Вниз» (под остальные).

### Группировка объектов

- Выделите несколько объектов и нажмите **правую кнопку мыши** — на холсте по
  любому из выделенных, либо по строке в панели «Слои». Откроется контекстное
  меню: **«Сгруппировать»**, **«Разгруппировать»** (когда объекты уже в группе) и
  **«Удалить»**. Меню одно на оба места (`ObjectContextMenu`, состояние в
  `ui.contextMenu`), поэтому действия везде одинаковые.
- В «Слоях» группа показывается строкой с **иконкой папки** («Группа 1 ·
  объектов: 2»), её объекты вложены с отступом, а кнопка-шеврон
  **сворачивает и разворачивает** список.
- **Клик по строке группы** выделяет **все** объекты группы — рамка трансформера
  охватывает их целиком, двигать и тянуть можно вместе.
- **Клик по объекту** (и в списке, и на холсте) выделяет **только его** — группа
  при этом не расширяется. Чтобы работать со всей группой, выделите её рамкой на
  холсте или кликните по строке группы в «Слоях».
- **Двойной клик по строке группы** сворачивает и разворачивает её (у объекта —
  по-прежнему открывает «Свойства» и правку текста).
- Кнопки строки группы (выше/ниже, скрыть, блокировка, удалить) действуют на все
  её объекты сразу.
- Группировка пишется в историю (`Ctrl+Z` возвращает как было).
- Проверка: `pnpm check:groups` (29 проверок: меню на холсте и в «Слоях»,
  общий groupId, строка группы с папкой и отступом, выделение всей группы,
  выделение одного объекта и на холсте, и в списке, двойной клик по группе,
  сворачивание/разворачивание, «Разгруппировать», удаление группы).

- **Название слоя — это инструмент, которым создан объект:** «Прямоугольник»,
  «Эллипс», «Линия», «Стрелка», «Текст», «Штамп», «Печать», «Подпись», «Рисунок»,
  «Изображение», «Закрашивание», «Выделение».
- **Одинаковые названия нумеруются снизу вверх** — «Прямоугольник 1» (самый
  нижний), «Прямоугольник 2»… Если объект такой один, номер не добавляется, а
  добавление нового объекта сверху не сбивает номера у существующих
  (`src/utils/layers.ts`, покрыто тестами).
- **Индикатор цвета** слева от названия: у фигур — заливка (если её нет —
  обводка), у текста — цвет текста, у штампа — цвет шаблона, у рисунка —
  цвет первого штриха. Если цвета нет (например, прозрачная заливка),
  показывается значок типа объекта.
- **Заголовок в «Свойствах»** показывает то же название, что и в «Слоях»
  («Прямоугольник 2», «Эллипс»), а ниже — дополнительную строку (текст объекта,
  название штампа).
- **Переименование.** В «Свойствах» → «Служебное» → «Имя объекта» можно задать
  своё имя: оно сразу появляется и в заголовке свойств, и в панели «Слои»
  (одинаковые имена нумеруются), участвует в истории (`Ctrl+Z` возвращает
  название по инструменту) и сохраняется в проекте. Пустое поле — снова
  название инструмента; фабрика объектов имена по умолчанию не проставляет
  (`src/utils/layers.ts`, `layerName`).
- **Панель «Слои»:** в каждой строке — маленькие кнопки ↑ «Выше» и ↓ «Ниже» с
  подсказками (не нужно выделять объект), внизу панели — «Поверх всех»,
  «Поднять», «Опустить», «Позади всех», а также удаление.
- Кнопки порядка **не отключаются**: если слой уже на самом верху или в самом
  низу, появляется сообщение «Слой уже наверху/внизу»; если ничего не выделено,
  нижние кнопки подсказывают выделить слой. Отключённая кнопка не показывает
  подсказку и не реагирует на клик — именно это выглядело как «не работает».
- **Горячие клавиши:** `]` — поднять, `[` — опустить.

### Обводка фигур: «Без цвета» и нулевая толщина

- В палитре цвета обводки (и в свойствах фигуры, и в параметрах инструмента)
  есть пункт **«Без цвета»**: `payload.stroke` становится `null`, обводка не
  рисуется ни на холсте, ни в PDF.
- **Толщина 0** — это тоже «без обводки», а не «тонкая по умолчанию». Раньше
  `Math.max(0.5, …)` и `0 || default` подменяли выбор: у линий и стрелок
  оставалась линия 0.5 pt, а новая фигура из инструмента получала дефолтную
  толщину из настроек. Теперь значения из параметров инструмента берутся как
  есть (`src/composables/useEditorTools.ts`, `konvaObjectFactory.ts`,
  `pdfExportService.ts`).
- Проверка: `pnpm check:canvas-tools` (фигуры с обводкой 3 pt, затем толщина 0 у
  всех — красных пикселей ноль; «Без цвета» из палитры; ввод 0 в поле «Толщина»;
  и разбор самого PDF — сколько раз в потоке задаётся красная обводка).

### Линии и стрелки

- **Заливки у них нет** — цвет линии всегда берётся из обводки, поэтому поле
  «Заливка» скрыто и в свойствах, и в параметрах инструмента. Там же поправлены
  подписи: в свойствах у линии и стрелки — «Цвет» и «Толщина», в параметрах
  инструмента — «Цвет линии» и «Толщина линии» (у прямоугольника и эллипса
  остаются «Цвет обводки»/«Толщина обводки»).
- **Штриховая линия:** «Сплошная», «Штрих» (штрихи), «Пунктир» (точки) и
  «Штрих-пунктир» (чередование длинного штриха и точки). Шаблоны заданы в
  `DASH_PRESETS` (`src/constants`), их одинаково понимают Konva и pdf-lib.
  Промежутки выбраны с запасом: круглый конец линии «съедает» половину толщины
  с каждой стороны, и при маленьком промежутке пунктир сливался в сплошную.
  Варианта «Точки» больше нет — он дублировал пунктир и назывался неверно.
- **Круглые концы штрихов у всех фигур**, а не только у линий: у прямоугольника,
  эллипса, треугольника и многоугольника тоже задан `lineCap: 'round'`, а в PDF —
  `borderLineCap: LineCapStyle.Round`. Без этого «Пунктир» у замкнутых фигур
  выглядел короткими «рисками», тогда как у линии — точками.
- **Наконечники стрелки** работают: «На конце», «С двух сторон»,
  «Без наконечника» — и на холсте (`pointerAtBeginning`/`pointerAtEnding`
  у `Konva.Arrow`), и в PDF (`drawArrowHead` рисует треугольник с нужного конца).
- **Курсор поворота.** При наведении на ручку поворота над выделенным объектом
  показывается дуга с двумя наконечниками, а не крестик: в браузере нет
  штатного курсора «поворот», поэтому картинка рисуется в canvas и отдаётся
  PNG-ом (`src/utils/cursors.ts`) в `rotateAnchorCursor` трансформера Konva.
- Проверка: `pnpm check:shape-styles` (отсутствие «Заливки», пункты списка
  штриховки, число отрезков и их длины для штриха/точек/штрих-пунктира,
  наконечники по пикселям у обоих концов, число треугольников в PDF, подписи
  полей и курсор поворота).

### Редактирование текста на холсте

- Инструмент **«Текст»** + клик по странице создаёт небольшую область и сразу
  показывает **мигающую каретку** — можно печатать, не заходя в панель свойств.
- **Текст и каретка — по центру точки клика**: рамка объекта сдвигается так,
  чтобы точка клика стала серединой «чернил» первой строки, и такой же отступ
  получает оверлей ввода (`padding-top`), поэтому каретка начинается на одной
  высоте с текстом. Отступ считается по реальной рамке глифов
  (`measureInkMetrics` — `actualBoundingBoxAscent` + `…Descent`), а не по ascent
  шрифта; общая функция — `textInkCenter` в `services/textRenderService`.
- **Рамка растёт по тексту**: ширина считается по естественной ширине строки
  (`computeTextBlockLayout` с широкой рамкой), высота — по числу строк. Рамка
  только увеличивается, поэтому текст не «прыгает» при удалении символов.
- **Клик по готовому тексту** инструментом «Текст» открывает его на правку, а
  каретка встаёт **в место клика** — позиция считается той же раскладкой, что и
  у рендерера (`caretOffsetAtPoint` в `src/utils/textCaret.ts`).
- Технически поверх объекта показывается `<textarea>` с прозрачным текстом
  (`TextInlineEditor`): он принимает клавиши и рисует каретку, а **сам текст всё
  время рисует Konva**. Так метрики DOM и Konva не расходятся, и после потери
  фокуса текст не «съезжает» (проверка сравнивает рамку «чернил» до и после
  `Esc` — сдвиг 0 px).
- Завершение — `Esc` или клик в другое поле; одна правка даёт один шаг истории.
  Поле в «Свойствах» остаётся как второй способ правки (по клику пользователя;
  автоматически фокус больше не перехватывает).
- **Пустой текст на холсте не остаётся**: если ничего не ввели или всё стёрли
  (пробелы и переводы строк не считаются содержимым), объект удаляется при
  **любом** способе выйти из правки — Esc, клик по холсту, смена выделения,
  переключение инструмента. Удаление живёт в наблюдателе за editingTextId, а не
  только в обработчике Esc.
- **Пробел в конце слова ничего не раздувает**: ширина считается по самой длинной
  строке напрямую (`measureTextWidth`), а не через раскладку — та не учитывала
  пробелы в конце строки, и пробел «переносился» на новую строку, отчего поле
  становилось вдвое выше.
- **Растягивание за сторону не искажает текст**: в обработчике `transform`
  трансформера масштаб сразу переводится в ширину/высоту объекта, а `scale`
  сбрасывается в 1 — текст перерисовывается при новой ширине и переносится по
  словам (как в текстовом редакторе), без «резины».
- **Ручки трансформации доступны при любом инструменте**: создали фигуру или
  текст — они остаются выделенными, и их можно растянуть или повернуть, не
  переключаясь на «Выбор». Нажатия на ручки не запускают рисование
  (`isStageChrome` в `useEditorTools`), а сам инструмент после трансформации
  остаётся прежним. Проверка: `pnpm check:transform` (17 проверок).
- Проверка: `pnpm check:text-inline` (34 проверки: каретка при создании, набор
  текста, рост рамки, пробел, удаление пустого текста, Esc, вход в правку по
  клику с кареткой в месте клика, растягивание без масштаба).

### Подсказки про Shift

Подсказка оформлена заметной карточкой: мягкий акцентный фон, иконка клавиатуры
и клавиша `Shift` в виде чипа (`<kbd>`), дальше — что именно получится
(квадрат, круг, правильный треугольник, многоугольник в квадрате, линия под 45°).
Текст подсказки свой для каждого инструмента (`shapeHintTail` в
`ToolOptionsPanel`).

Важная деталь реализации: Konva рисует узлы **в порядке добавления**, поэтому
недостаточно поменять `zIndex` в сторе — после синхронизации узлы
переставляются по порядку объектов (`useObjectRenderer.sync()`). Без этого
порядок менялся только в данных, а на холсте не менялось ничего.
Проверка: `pnpm check:layer-order` (складываем три цветных прямоугольника и
сверяем цвет пикселя после каждого действия, в том числе без выделения).

## Шрифты: как добавить свой (например, Times New Roman)

Окно «Шрифты» открывается с любой страницы приложения:

- **редактор:** кнопка со значком шрифта на панели инструментов, а также
  **«Экспорт» → «Шрифты»** (кнопка есть и внизу окна, даже если документ не открыт);
- **настройки:** раздел про шрифты → **«Управление шрифтами»**;
- **главная страница:** значок шрифта в шапке;
- **горячие клавиши:** `Ctrl + Shift + F`.

1. Нажмите **«Загрузить TTF или OTF»**.
2. Windows: файлы лежат в `C:\Windows\Fonts` — у Times New Roman это `times.ttf`
   (обычный), `timesbd.ttf` (жирный), `timesi.ttf` (курсив), `timesbi.ttf`
   (жирный курсив). macOS: Font Book → правый клик → «Показать в Finder».
3. Можно выбрать сразу все файлы: начертания с одинаковым названием семейства
   объединяются в **один** шрифт, и редактор сам подставляет жирное или курсивное
   начертание в зависимости от оформления текста.
4. Шрифт появляется в списке шрифтов инструмента «Текст»; кнопка «Сделать
   основным» назначает его шрифтом по умолчанию.

Шрифт хранится локально в браузере (IndexedDB) и никуда не отправляется.
Сразу после загрузки приложение проверяет, можно ли встраивать его подмножеством
(см. раздел про кириллицу), поэтому готовый PDF остаётся компактным.

Загружайте только те шрифты, которые вы вправе использовать в документах. Если
нужен свободный аналог Times New Roman — подойдёт Liberation Serif или Tinos.

## Поворот страниц

Поворот нужен для страниц, отсканированных боком, и для документов, у которых
ошибочный `/Rotate`.

- **Где:** кнопки ⟲ ⟳ на панели инструментов, раздел «Поворот страницы» на
  вкладке «Страница» справа, кнопки при наведении на миниатюру страницы.
- **Горячие клавиши:** `Alt + ←` и `Alt + →` — повернуть текущую страницу.
- **Все страницы сразу:** «Повернуть все страницы на 90° вправо/влево» на
  вкладке «Страница», там же сброс поворотов.
- **Как хранится:** поворот пользователя лежит отдельно от исходного `/Rotate`
  страницы (`PdfPageState.viewRotation`), итоговый угол — их сумма. В выходной
  PDF записывается только `/Rotate`, содержимое страницы не перезаписывается,
  поэтому качество сканов не страдает, а исходную ориентацию можно вернуть
  одной кнопкой.
- **Аннотации:** при повороте все объекты страницы пересчитываются в систему
  координат нового угла (`remapObjectsForPageRotation`), поэтому текст, штампы и
  корректор остаются ровно на тех же местах страницы. Поворот и перенос объектов
  — одно действие в истории, `Ctrl+Z` возвращает и ориентацию, и координаты.
- **Что видно в интерфейсе:** миниатюры и рабочая область перерисовываются с
  новым углом, у повёрнутых страниц в списке появляется метка угла.

## Модель данных (кратко)

Каждый объект — структурированные данные, а не «приклеенные пиксели»:

```ts
interface EditorObject {
  id: string;
  type: 'text' | 'image' | 'shape' | 'drawing' | 'signature' | 'stamp' | 'whiteout' | 'highlight';
  page: number;            // 0-based
  x: number; y: number;    // pt, левый верхний угол
  width: number; height: number;
  rotation: number;        // градусы, по часовой стрелке
  opacity: number;
  visible: boolean;
  locked: boolean;
  zIndex: number;
  groupId?: string | null;
  createdAt: string; updatedAt: string;
  payload: TextPayload | ImagePayload | ShapePayload | DrawingPayload
         | SignaturePayload | StampPayload | WhiteoutPayload | HighlightPayload;
}
```

Объекты неизменяемы: любая правка создаёт новые экземпляры, поэтому снимки истории —
это просто копии массива ссылок (undo/redo работает быстро и предсказуемо).

## Сохранение: проект в браузере и файл на диск

Две разные вещи, и они специально разделены:

| Кнопка | Что делает |
| --- | --- |
| **«Сохранить»** (`Ctrl+S`) | Пишет **проект в IndexedDB**: PDF-страницы, объекты, настройки и историю. Ничего не скачивается. Проект появляется на главной в блоке «Локальные проекты» и открывается оттуда двойным кликом. Повторное сохранение обновляет тот же проект (`pdf.currentProjectId`, иначе отпечаток файла). |
| **«Экспорт»** (`Ctrl+E`) | Собирает файл и **скачивает** его: PDF с аннотациями, плоский PDF, PNG/JPEG/WebP, DOCX, проект JSON, SVG. |

Устройство сохранения проекта:

- `exporter.saveProject()` (`composables/useExport.ts`) → `exportStore.saveProjectToStorage()`
  → `serializeProject()` → `storageService.projectSave(id, project)`;
- идентификатор: `pdf.currentProjectId` (если документ открыт из проекта) →
  `pdf.fingerprint` (отпечаток исходного PDF) → новый `project_…`;
- `currentProjectId` сбрасывается при открытии другого файла, создании пустого
  документа и очистке (`stores/pdf.ts`), поэтому «Сохранить» после открытия
  нового файла создаёт отдельный проект;
- на главной странице список обновляется при возврате из редактора
  (`watch` на маршрут в `StartView.vue`), кнопка «Все» открывает окно «Проекты»
  с удалением и списком целиком.

Проверка: `pnpm check:projects` (14 проверок: сохранение кнопкой, запись в IndexedDB,
появление на главной, открытие обратно с объектами, повторное сохранение не
создаёт дубль).

## Экспорт PDF: конвейер

1. Исходный PDF берётся как `ArrayBuffer` (он сохраняется при загрузке документа).
2. `PDFDocument.load()` (при необходимости страницы копируются только выбранные).
3. `registerFontkit()` и встраивание нужных TTF-начертаний с подмножествами.
4. Для каждой страницы: `getMediaBox()` + `getRotation()`, объекты сортируются по `zIndex`.
5. Каждый объект рисуется в собственной локальной системе координат: точка привязки
   переводится в PDF, поворот передаётся как `pageRotation − objectRotation` —
   поэтому объекты совпадают с предпросмотром даже на страницах с `/Rotate`.
   - текст → `drawText` (посимвольно при межбуквенном расстоянии, синтетический курсив через `xSkew`);
   - фигуры → `drawSvgPath` / `drawEllipse` / `drawLine`;
   - изображения → `embedPng` / `embedJpg`;
   - рисунки и подписи → векторные контуры (perfect-freehand), заливка `drawSvgPath`;
   - штампы → векторно (рамки, круговой текст по символам, логотип), с растеризацией
     в высоком разрешении как резерв;
   - закрашивание → `drawRectangle`, выделение → `drawRectangle` с `blendMode: Multiply`.
6. Метаданные записываются в Unicode, документ сохраняется (`useObjectStreams: true`).
7. Результат отдаётся как `Blob` и скачивается с корректным именем файла.

Важно про SVG-пути: `page.drawSvgPath` сам переворачивает ось Y (`scale(1, -1)`),
поэтому путь задаётся «как на экране» (y вниз), а точка привязки — левый верхний
угол объекта. Если путь дополнительно перевернуть (`flipY`), фигура выходит
перевёрнутой на 180° — именно так ломались треугольники и многоугольники.
Проверка: `pnpm check:export-pages` (раздел 6 сверяет координаты вершины в
потоке PDF).

## Растровый экспорт (PNG/JPEG/WebP) и DOCX

- Объекты рисуются на Konva-сцене по одной странице: в `renderPageCanvas` они
  фильтруются по `obj.page === pageIndex`, поэтому содержимое первой страницы не
  попадает на остальные (DOCX собирается из тех же изображений).
- Холст создаётся в **пикселях** (`displayWidth × dpi/72`), а объекты хранятся в
  **точках**, поэтому слой объектов масштабируется на этот коэффициент. Без
  масштабирования при `dpi > 72` вся композиция съезжала в левый верхний угол.
- Фон (отрисованная страница PDF) лежит на отдельном, немасштабируемом слое —
  он уже нужного размера.
- Проверка: `pnpm check:export-pages` (растр по страницам, положение объекта при
  dpi 144, экспорт png/jpeg/webp/docx).

## Приватность и безопасность

- Файлы не покидают устройство; сетевые запросы нужны только для загрузки статических ресурсов
  самого приложения (шрифты, воркер pdf.js).
- Встроенный JavaScript PDF не выполняется (`isEvalSupported: false`), внешние шрифты
  не подгружаются (`useSystemFonts: false`).
- Содержимое документов не логируется.
- Объектные URL освобождаются после использования.
- Для защищённых файлов показывается предупреждение, а пароль используется только локально.

## Ограничения

- pdf-lib не расшифровывает зашифрованные PDF: такие файлы открываются, но для них
  рекомендуется экспорт в изображения (приложение предупреждает об этом).
- Сложные эффекты текста (обводка букв) в PDF не переносятся — вместо этого используется
  тень/ореол, который поддерживается и в PDF, и в предпросмотре.
- Скругление углов изображений в PDF не поддерживается (при экспорте выводится
  предупреждение, изображение остаётся прямоугольным).
- Прямая правка текста исходного PDF не выполняется: используется корректурный слой
  (закрашивание + новый текст), как и рекомендовано в задании.
